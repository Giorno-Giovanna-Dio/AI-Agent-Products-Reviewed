## 產品介紹

AxisAgentic 是 XYZ AI Lab 的開源 Python 框架。它給長程、會用工具的 agent 一個可換零件的執行期，並把每次執行寫成可回放的軌跡。使用者是要跑搜尋基準、回收軌跡、再交給外面訓練的研究者，不是坐在桌面 ADE 裡看終端機的人。公開的參考配方是 Web Search 和 WideSearch：一題一位會搜尋、讀頁、必要時跑程式的研究員。套件不含模型權重。實驗室的技術報告在 [AI4AI at Scale](https://xyz-lab.ai/blogs/ai4ai-at-scale/)。本次只讀 `main` 的 README、LICENSE、docs 與公開 recipe，沒有安裝。

一套 recipe 用嚴格的 YAML 把模型端點、資料集、回合上限、工具和評分組起來。排程器同時開有限個任務，每個任務有自己的 orchestrator。跑完的軌跡可以恢復、重判、在 Streamlit 儀表板裡對照，或匯出成訓練樣本。儀表板是實驗成績單，不是這個產品的工作空間。

## 主要 Features

### 一題一席，可以再試

公開配方裡，一個任務就是一位研究 agent 對一道題。系統提示要求一回合最多叫一個工具：先搜尋、再讀頁，證據夠了就把答案放進 `\boxed{}`。範本也關掉平行工具呼叫。Web Search 覆蓋 BrowseComp、BrowseComp-ZH、DeepSearchQA、GAIA、Humanity's Last Exam、LiveBrowseComp。WideSearch 對同一題排多次 trial，再用表格對齊，算列與項目的 F1。

外層還有 attempt。重試次數用完才停。失敗時可以先寫一張檢討（做了什麼、卡在哪、哪些發現還能用），下一棒帶著這張紙重來。範本預設不帶檢討，重試次數也是 0，所以預設就是一試定案。

交出框住的答案之後，可以打開自我檢查：同一個模型再用工具核對題目條件，判錯就重答，次數有上限。這是這位研究員自己複查，不是請人點頭。範本預設打開。

核心另有一個接口，可以把另一個 orchestrator 包成工具，並記下巢狀層級。公開的 web_search 與 wide_search 沒有註冊這個工具。多員工編制在這份公開程式裡還沒接上。

### 桌上看得到的，和櫃子裡的全紀錄

完整對話只追加、不改寫。模型每一拍真正看到的訊息，是用標記從這份紀錄導出來的。三種標記會改桌面，不會把櫃子裡的紙毀掉：

- **壓縮**：每隔若干回合，把較早的來回收成一段摘要，最近幾輪仍原文留著。
- **全部清空**：上下文快滿時，桌面只留系統說明和原題，中間的工具往來從視野拿掉，也不寫摘要。壓縮和清空不能同時開，範本兩者都關。
- **回滾**：重複的搜尋、工具錯誤，或撞到拒答字句，可以把剛寫下的那一拍從視野拿掉再生成。回滾有次數上限，超過就照單全收。上下文爆掉時，還有剩餘重試就整段重來；已經是最後一次，就把最近一次工具往來捲回去，強迫交最終答案。

推理內容可以跟著之後的請求一起送回。較舊的工具結果也可以改成「省略」佔位；範本預設全部保留。

### 工具、沙箱與上限

工具管理員負責註冊、檢查參數、修參數、執行上限和追蹤。搜尋走 Serper，抓頁走 Jina，可選另一個模型做摘錄。程式執行預設關閉。打開後，這一次 attempt 共用一間 E2B 沙箱：`python_exec` 是有狀態的筆記本，`shell_exec` 跑指令，兩者看得到同一套檔案。沙箱在第一次呼叫時才建立，attempt 結束就拆掉。沒有用到程式的任務不會去開沙箱。公開設定看得到開關、逾時和呼叫上限，沒有細項權限清單。沙箱裡實際能做什麼，尚未實測。

模型端是 OpenAI 相容端點，也可以換成別的客戶端。傳輸層的逾時和限流重試不消耗任務的重試額度。設定註解寫，端點連續失敗太久會讓程序退出。

### 軌跡、評判與匯出

每個任務寫下軌跡、時間、token、工具呼叫、狀態，以及解析後的設定。跑的過程會增量更新評分和儀表板用的摘要，所以長跑還沒結束也能看。完成的目錄預設受到保護。`--resume` 重用已完成的任務；要改已收尾的目錄，得刻意加力。

評判是另一個模型，或精確比對，可以事後重判，不必重跑推論。工具成功或失敗會記一筆分數，那是給外部訓練的鉤子，不是人的評語。

SFT 匯出會重播那些可見性標記，所以被回滾、被壓縮掉、被清空的歷史不會進監督樣本。外面的訓練自己決定對錯過濾和優化。repo 裡的強化學習只留 rollout 的邊界，不含完整的線上訓練。技術報告也寫明，篩過的 answer-conditioned RL 方案沒有訓練到最後的驗收關卡。

Streamlit 儀表板可以左右對照兩次實驗：準確率、耗時、軌跡長度、工具統計、單題軌跡、生效設定和提示詞。這是研究用的成績板。

## 主打賣點

- **它加上的是「全紀錄」和「當時看得到的上下文」這兩層。** 回滾、壓縮、清空都寫成標記。回放時能重建模型那一拍真正看見的桌子。同一份紀錄同時服務恢復、評分和訓練匯出。
- **和 CrewAI 不同。** CrewAI 是一組有角色的小隊，用流程交接。AxisAgentic 的公開配方是一位長程研究員，自己搜、自己讀、自己把答案框起來，再自己複查。人不是在場派工的經理，而是實驗操作員：開跑、恢復、重判、挑軌跡。
- **XYZ-Aquila 是用這套 runtime 做出的搜尋系統。** 基準數字來自實驗室的技術報告，不是這次實測。報告自己也說，圖裡有些基線來自不同 harness，只能當基準對照，不能當成統一排名。
- 儀表板、嚴格 YAML、可換的工具和評分器，是把這條執行環包成可重現的實驗。開源核心仍是 runtime 和軌跡。

## 使用情境

### 一道長題，搜很多輪才交卷

- 適合誰：要在 BrowseComp 這類題上跑深搜的研究者。
- 在什麼情況使用：題目需要反覆搜尋和讀頁，回合數以百計，上下文可能爆掉。
- 帶來的價值：回合、工具和上下文策略寫在 YAML。桌面怎麼被壓縮或清空，都留在軌跡裡。

### 同一題再試，或並排試多次

- 適合誰：想看失敗後換策略，或要 WideSearch 那種多次 trial 的人。
- 在什麼情況使用：打開失敗檢討再重試，或對同一題排多個 trial。
- 帶來的價值：下一棒可以帶著上一棒的檢討。多次 trial 的分數會邊跑邊寫出來。失敗檢討預設是關的。

### 跑完再挑哪些軌跡可以送去訓練

- 適合誰：要對照兩次實驗、重判答案、再匯出訓練樣本的人。
- 在什麼情況使用：長跑中斷後 resume，或在儀表板看單題軌跡，再匯出。
- 帶來的價值：匯出用的是模型當時看得到的歷史，被收回的動作不會混進樣本。人是在事後挑選，不是在每一輪按核准。任務進行中的人工放行，公開文件裡沒有看到。

## 我們可以學什麼

- 值得借鑑的 product idea：員工不是一組角色，而是一題一席的長程研究員。工作是原題，加上要框起來的答案。記憶不是跨日資料庫，而是這一次 attempt 的可見上下文；櫃子裡另存完整軌跡。交接發生在工具結果回到同一張桌子，以及失敗檢討交到下一次 attempt。
- 值得借鑑的 interaction / workflow：壓縮是把舊紙收成一頁摘要，最近幾頁仍攤開。清空是把桌面掃回原題，不寫摘要。回滾是把剛做錯的搜尋從桌上抽走。自我檢查是同一人站起來核對條件再重寫。人的工作在座位之外：恢復中斷的位子、重判答案、左右對照兩次實驗、決定哪份軌跡可以帶出門。
- 在 2D workspace 裡會變成什麼：一張俯視的研究樓層。每一道題是一張固定工位，名牌是題目，座位上只有一位研究員。桌面是模型這一拍看得到的紙。工位旁的櫃子是只追加的全紀錄，回滾和清空的紙都在櫃子裡，不在桌上。手伸向已經用過的查詢會被擋回來。上下文快滿時，要嘛舊紙收成摘要頁，要嘛桌面被掃回原題卡，兩種不會同時發生。自我檢查是同一人離桌對答案，不另請一位同事。WideSearch 是同一題並排的幾張 trial 桌。E2B 沙箱是這次 attempt 才拉出來的側桌，結束就收走。人走在走道上看誰還在搜、誰在交卷、誰的回合快用完。蓋章發生在跑完之後，挑哪些工位的可見紙張可以送去訓練。牆上的成績板是 Streamlit 儀表板，那是分數，不是這層樓。
- 在 3D workspace 裡會變成什麼：可走進的辦公室，如同 [Agent Office](https://github.com/AgentSystemLabs/agent-office)。你走進研究樓層，看見每一題的工位上誰在場：這位研究員正在搜尋、讀頁、在側桌寫程式，或站在桌邊核對框住的答案。桌面只有當時看得見的上下文。打開櫃子才看得到被收回、被壓縮、被掃掉的那一段。下一次 attempt 是同一人再坐下，桌上也許多一張上一棒的失敗紙條。WideSearch 是同一道題的一排 trial 座位，走過去就知道哪一席還在做、哪一席已經交卷。人不是在任務中途被叫去點頭。你走完一圈，看誰卡在很長的回合裡，再決定哪一張桌子的可見歷史可以帶出辦公室。重點是看見誰在哪一席做事。
- 需要重新設計的地方：公開配方沒有多角色交接，也沒有任務中的人工放行。若辦公室要放 CrewAI 那種小隊，或 Paperclip 雇來的外部員工，不能把這一席研究員直接當成整間公司。巢狀 orchestrator 的接口存在，但這兩個公開 recipe 沒有用它，先不要做成經理桌。儀表板的左右對照留在牆上，不要把它做成地板。沙箱只有開關和上限，細項允許清單尚未確認。套件版本在 `setup.py` 是 0.1.0，changelog 記 2026-07-23；這次查到的 GitHub tags 是空的，tag 是否已推上，尚未確認。基準分數來自技術報告，尚未實測。

## 初步看法

- 最有價值的部分：可見上下文和完整軌跡分開。回滾、壓縮、清空都能回放。桌上有什麼，和曾經發生什麼，可以同時存在。
- 最大限制或疑問：它是給研究者批次跑的 runtime。一位長程 agent 如何在空間裡被看見，文件沒有畫面。自我檢查和評判都是另一個模型呼叫，不是人。
- 是否值得進一步研究或親自體驗：值得。尤其是一席研究員的桌面、櫃子、側桌沙箱，以及人在事後挑選軌跡。Status 維持 `untried`。

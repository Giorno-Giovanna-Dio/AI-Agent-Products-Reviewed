## 產品介紹

Hello-Agents 是 Datawhale 的開源教程《從零開始建構智能體》。它服務想從原理走到能自己做出多智能體應用的人：有 Python 基礎、會呼叫大語言模型 API 的開發者、學生與自學者。讀法是線上書（[國外](https://datawhalechina.github.io/hello-agents/)、[國內加速](https://hello-agents.datawhale.cc)），對照 repo 裡的 `docs/` 與 `code/`，自己跑、改每一章的程式。這不是一間已經開著的辦公室，也不是桌面 ADE。本次只讀 README、LICENSE、目錄與關鍵章節，沒有安裝。

教程把「軟體流程派」（文件點名 Dify、Coze、n8n）和「AI 原生智能體」分開，並把後者當成主線。路上仍會先用低代碼平台與現成框架練手，再到第七章做出自己的框架。那個可 `pip` 安裝的框架叫 HelloAgents，原始碼在另一個倉庫 [jjyaoao/HelloAgents](https://github.com/jjyaoao/HelloAgents)（教程連結寫成 `jjyaoao/helloagents`）。對方 README 自述這是基於本教程的框架：`learn_version` 分支對應教程正文，`main` 的 v1.0.1 是按現行源碼維護的工程版，歷史版本 v0.1.1 到 v0.2.9 各對教程的一章。教程負責人帳號也是 jjyaoao。兩份要分開看：這一個 Cell 是課程怎麼把概念排成一條路，框架倉庫才是可安裝的執行期。本次沒有逐章比對 `learn_version` 和正文是否仍然一致。

## 主要 Features

### 五段課程，先分清流程與自主

課程分成基礎、自己做出智能體、進階、三個綜合案例、畢業設計。第一章就把 Workflow 和 Agent 分開：流程是事先寫死的步驟與條件；智能體是帶著目標，依當下資訊自己拆步驟、選工具、再回答。後面的練習都站在這個分別上。第五章走低代碼平台（導讀以 Coze 為例），第六章再用 AutoGen、AgentScope、CAMEL、LangGraph 各做一個小協作，然後第七章才收成自己的框架。

### 同一套框架裡的幾種員工

第七章的 HelloAgents 把核心收成很少的物件：訊息、設定、Agent 基底，再加上工具。範式做成不同員工：SimpleAgent 是一問一答；ReActAgent 是想、動手、看結果再想；ReflectionAgent 是先交草稿再被審查改寫；PlanAndSolveAgent 是先寫完整計畫，再一步步執行並記住已完成的步驟；FunctionCallAgent 把供應商的函式呼叫再包一層。設計上除了 Agent 以外「萬物皆為工具」：記憶、RAG、強化學習、MCP 都不另開一套概念，而是掛到同一個工具牆。每一章的教學程式會做成可 `pip` 下載的歷史版本。教程第七章示例是 `hello-agents==0.1.1`，第八章提到 0.2.0 與 0.2.9。框架 README 說 v0.1.1 到 v0.2.9 各對一章；哪一章對哪一個版號，本次沒有逐章核對。

### 記憶、檢索與開工前的上下文

第八章把記憶分成四種。工作記憶放在記憶體裡，會過期，重開就沒了，搜尋偏關鍵字。情節記憶用 SQLite 加 Qdrant，留具體事件。語意記憶用 Neo4j 加 Qdrant，抽實體與關係。感知記憶按文字、圖像、聲音分開存放。重要的工作記憶可以整理進情節，再整理成語意；也會依重要性、時間、容量遺忘。RAG 是另一條線：上工前放上書架的文件，不是這次對話裡發生的事。

第九章的 ContextBuilder 用 GSSC：從多處 Gather 候選、按相關與新近 Select、分成可讀區塊 Structure、超限再 Compress，而且盡量每個區塊都留一點。NoteTool 把任務狀態、阻塞與下一步寫成結構化筆記，留到下一次。TerminalTool 是現場翻檔案：教程描述工作目錄不能逃出、指令有允許清單、逾時約 30 秒、輸出過大就截斷。這些限制尚未實測。

### 三種協定都掛在工具上

第十章把 MCP、A2A、ANP 都包成 Tool，同一種 `run()`，智能體不用各自學一套客戶端。MCP 是智能體對工具與資源（檔案、GitHub 等），可走本機 stdio 或遠端傳輸。A2A 是智能體對智能體：一邊把技能開成服務，另一邊來請求。ANP 在教程裡是服務註冊、發現與把任務派給負載較低的節點；文件寫明這是輕量自研模擬，官方另有 AgentConnect，這裡只做概念。ANP 能否當正式發現服務，尚未確認。

### 案例、評估與畢業交件

第十二章把評估收進同一套框架：BFCL 看工具呼叫是否對、GAIA 看通用助手題、另外有 LLM 評判、勝率比較，以及一個給人看的驗證介面。第十一章是 Agentic RL（SFT 再到 GRPO），教的是把模型送去訓練，不是每天的辦公桌。

三個案例把前面的零件裝起來。旅行助手是四個專家依序工作：景點、天氣、酒店各自呼叫地圖工具，規劃者只負責把結果收成行程；人可以改行程、看進度、匯出。深度研究是 TODO：規劃者把題目拆成幾條子任務，總結者讀搜尋結果並寫進 NoteTool，報告者再收成一份報告；協調者一次只讓一個人做。賽博小鎮是 Godot 前端加 FastAPI：每個 NPC 是一個 SimpleAgent，帶職業與性格、工作記憶與情節記憶、五級好感度；玩家走過去按鍵對話，背景還會批次生成沒人在看時的對話。第十六章要學員 fork、在共創目錄交一個自己的多智能體專案，用 Pull Request 接受審閱。

## 主打賣點

- **它最想被記住的是「從使用者變成建構者」這條路。** 先分清流程和自主，再親手做 ReAct、計畫、反思，然後收成一個刻意做小的框架。賣點是順序與可讀，不是又一個功能清單。
- **真正不同的地方是「萬物皆為工具」加上章節版本。** 記憶、檢索、協定、評估都掛回同一個 Agent 呼叫工具的動作。每一章對應一個可安裝的框架快照，所以後面的案例是在加工具，不是換一套世界觀。
- **和 CrewAI 同類的是角色、任務、交接。** CrewAI 把 role、task、process 做成同一次 Python 執行裡的小隊。這份教程把同樣的想法拆開來教：範式是不同員工，案例才把他們排成順序交接。它沒有現成的辦公室畫面。
- **框架倉庫不要併進來。** [jjyaoao/HelloAgents](https://github.com/jjyaoao/HelloAgents) 是教程指向的執行期。本 Cell 只記課程怎麼組織人、任務、記憶與交件。
- ReAct、計畫求解、反思、MCP、RAG、向量庫，都是既有做法的教學包裝。低代碼那一章是對照，不是這份教程的終點。

## 使用情境

### 想看懂交接，而不只會呼叫框架

- 適合誰：會寫 Python、準備自己做多智能體應用的人。
- 在什麼情況使用：還分不清流程圖和會自己改計畫的智能體，或是被現成框架的抽象擋住。
- 帶來的價值：同一條路上先看到範式，再看到它們怎樣收成 Agent 加工具，案例才把多個人排起來。

### 用案例看一件工作怎麼被拆開

- 適合誰：要做研究報告、行程或「有角色的人在一個地方裡」這類成品的人。
- 在什麼情況使用：對照旅行助手的順序專家、深度研究的 TODO 與筆記、或小鎮 NPC 的記憶與好感度。
- 帶來的價值：看得到輸入、工具、產出與人可以改的那一步。這些是教學專案，不是已經部署的產品。

### 交件前先有一間評分室

- 適合誰：想在把智能體放進工作空間之前，先知道它會不會亂叫工具的人。
- 在什麼情況使用：沿第十二章的 BFCL、GAIA 與人工驗證來看一次執行。
- 帶來的價值：評分是獨立的一件事，和「把人畫在地圖上」分開。分數本身尚未實測。

## 我們可以學什麼

- 值得借鑑的 product idea：員工是一種範式加上角色提示；工作是目標拆成的任務，每項有意圖與期望產出；合作預設是順序交接，一次一個人。記憶、檢索、協定都是這個人可以走過去用的工具，而不是另一套產品。
- 值得借鑑的 interaction / workflow：開工前先組一份上下文（收集、挑選、分區、壓縮）。做過的事進工作記憶，隔夜要留的寫進筆記與情節記憶。人的介入是改行程、看研究進度、走過去跟某人說話、在驗證介面打分，以及畢業時用 Pull Request 審作品。
- 在 2D workspace 裡會變成什麼：一張俯視的平面訓練樓層，像 pixel 辦公室或學校地圖，人是在樓層上工作。門口是一間說明室，牆上並排兩張圖：一張是畫死的流程，一張是會依天氣改推薦的員工。練習區有幾張固定工位：ReAct 桌面上循環著想法、工具、觀察；計畫桌先把步驟釘在板子上再逐條做；反思桌是草稿與審查面對面傳紙。中間的工作台組裝員工，名牌只有訊息、設定與 Agent，其餘能力都掛在牆上一面工具牆。記憶是工位下的抽屜：會過期的工作托盤、情節檔案、語意櫃子、感知架子；另有一位整理員把重要紙條往更深的抽屜歸檔，太舊的丟掉。RAG 書架跟抽屜分開。開工前的桌子先把資料夾分成區塊，太厚就先壓薄。筆記留在桌上給明天。終端機是上鎖的檔案櫃，只能用允許的指令，不能走出這個資料夾。旅行專案房是一排四張桌子，地圖工具只有一個櫃台，紙依序傳過去，最後規劃者收成行程，人可以在結果桌上改字再匯出。研究室是一面 TODO 牆，同一時間只有一張桌子亮著，總結寫進筆記本，報告者最後裝訂。評分室貼著工具呼叫與問答的分數，旁邊有人的核對桌。共創翼是學員把自己的專案推進來等人審。賽博小鎮那一章本身是 Godot 的遊戲地圖，在這張樓層上它是一間獨立的案例教室，用來學「人站在哪、跟誰說話、關係分數怎麼改對話」，而不是把整座樓層換成遊戲。
- 在 3D workspace 裡會變成什麼：可走進的辦公室，如同 [Agent Office](https://github.com/AgentSystemLabs/agent-office)。重點是看見誰在場、誰在哪裡做事。你走進練習區，會看到 ReAct 那位正伸手拿工具再回到座位；計畫那位把步驟寫在白板，做完的留在板上；反思是兩個人隔桌傳草稿。旅行與深度研究都是順序房間：資料夾送到下一張桌子，上一個人停手，你走過去就知道現在輪到誰。MCP 是大家共用的工具櫃台。A2A 是拿著請求走到同事房裡。ANP 是接待處的名冊，告訴你誰比較有空；教程裡的 ANP 只是模擬，名冊先不要當成真的服務發現。工作記憶是桌上會被清掉的便條，情節記憶是可以打開的檔案櫃，語意記憶是櫃裡整理過的條目，人走過去抽一張，而不是把知識圖譜做成可旋轉的立體物件。上下文是這個人開口前已經放在桌上的分區資料夾。筆記與阻塞留在桌上，隔天還在。終端機是一間進得去、但指令被限制的小房間。人的位置也算數：你走到行程桌改一版、站在研究進度旁看報告長出來、在評分室坐下核對，或到門口收畢業專案。小鎮章教的是另一件事在這間辦公室裡的樣子：每位同事有職業與性格、短記憶與長記憶、以及會變的關係；你走過去才開口，沒人看的時候他們仍在背景裡產生對話。Godot 那個像素小鎮是教程的遊戲前端，這間可走的辦公室拿來上班，不拿來玩遊戲。
- 需要重新設計的地方：教程沒有「誰在哪一桌」的即時畫面，案例的網頁與 Godot 是各自的成品。空間辦公室要把章節版本、筆記、好感度、評分收成看得到的位置與物件。第十一章的訓練是把人送去另一間訓練室再回來，不要跟日常工位混在同一張桌上。框架的實際行為、各章 pip 版本對照、終端機沙盒與 ANP，都尚未實測，先不要寫死進介面。

## 初步看法

- 最有價值的部分：一條從範式到工具牆、再到順序交接與交件審閱的教學模型。記憶、上下文、協定被收成同一個人可以走去用的東西。
- 最大限制或疑問：它是書和章節程式，不是工作空間執行期。可安裝的 HelloAgents 在另一個倉庫。ANP、沙盒與評分是否如章節所寫，要跑過才知道。
- 是否值得進一步研究或親自體驗：值得，尤其是順序交接、筆記留在桌上、以及「走過去才對話」怎樣放進 2D 樓層與 3D 辦公室。Status 維持 `untried`。

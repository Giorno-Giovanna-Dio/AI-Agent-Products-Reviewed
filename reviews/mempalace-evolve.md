## 產品介紹

MemPalace Evolve 是給 AI agent 用的本機長期記憶。開發者用 Python、MCP，或本機 HTTP，把一段事實放進一個目錄，之後換一輪對話再把它找出來。它服務的是要讓 agent 跨回合記住決定與經驗的人。repo 作者標成 DreamSeed，授權 MIT，套件版本字串是 `0.1.0`。本次讀的是 GitHub `master`（2026-07-18 的 `b4fce4bd`）、README、文件與原始碼，沒有安裝。

記憶宮殿在這裡是一種放東西的方法。一座宮殿是一個目錄。一座翼（wing）把專案、使用者或某一個 agent 隔開。翼裡面的房間（room）是類別，例如決策、架構、設定、錯誤。每一則記憶是一個抽屜（drawer）。人要看的是：筆記先被放進哪一間房，之後怎麼被找出來、變淡，或搬到大家都能讀的走廊。

## 主要 Features

### 放進哪一間房

`remember` 把一段文字放進目前這座翼的某個房間，並可附來源、標籤、結構化欄位，或一段存活秒數（ttl）。房間會順便決定這則記憶跟誰共享。決策、設定、架構、偏好留在這座翼。一般內容和進度比較像這一輪發生的事。錯誤與錯誤模式被標成程序記憶，召回時每座翼都會再搜一次。相同內容，或相似度超過門檻的內容，會併回舊抽屜。決策、設定、架構裡，若新的一句和舊的很像又不一樣，舊抽屜會被蓋上「已被取代」。這是文字相似度的判斷。

`ingest` 把一個目錄裡的檔案切成塊，放進指定房間（預設 `documents`），並記下來源檔後來有沒有變。`digest` 用關鍵字從一段對話挑出候選句（決定、錯誤、架構、設定），直接放進對應房間。Claude Code 的 Stop hook 會在一輪結束時讀逐字稿、做 digest，再跑一次 `evolve`。

### 怎麼被找出來

`recall` 先搜目前這座翼，同時再搜程序記憶。ttl 過期的不會出現。排序把相似度、最近有沒有被打開、以及重要程度合在一起；標成過時或已被取代的會往下掉。被召回的抽屜會更新「最後被看過」，所以常被拿的比較不容易淡掉。同一輪裡問法很像的問題，會先用這次行程還攤在桌上的工作記憶。這份工作記憶只活在這次程式裡，關掉就沒有。

`context_for` 把召回結果收成可塞進提示的短清單，每行前面有房間名。召回也可以沿著知識圖譜再多拿相關抽屜。圖譜是本機 SQLite 裡的三元組（誰、什麼關係、對象），欄位可以帶有效時間，也可以指回某一個抽屜（`source_closet`）。SDK 的 `add_fact` 只寫三個詞，沒有填時間，也沒有填回抽屜。從對話自動抽關係，是用少數句型去配，主詞常常就是翼的名字。

程式裡另有一套四層記憶棧。第零層讀身份檔。第一層是這一翼最重要的約十五則，起床時先攤開。第二層按翼和房間直接取。第三層做深層搜尋，並跳過已標成被取代的抽屜。這套棧有自己的指令入口。主要 SDK 的 `recall` 沒有呼叫它。兩條路在實際使用時有沒有接成同一條，尚未確認。

### 怎麼進化

`evolve` 是一輪整理。若帶上逐字稿，它會抽出候選、打分：夠格的放進長期抽屜，太薄或像填空的丟掉，中間的留著。接著把今天很像的抽屜合併。分數低又很久沒人看的會被清掉。名叫 `candidate` 的翼裡，分數夠的會搬進專案翼。別的翼召回某一則、次數累到三次，就把它改成程序記憶，之後每座翼都能召回。很久沒被碰的決策會標成過時。`evolve` 的說明寫它會壓縮舊記憶；程式在這一步只數出有多少則可以壓。真正縮成短摘要、把原文放進歸檔，要另外呼叫 `compress`。

間隔複習是另一條線。被召回夠多次的抽屜會到期，人用 `review` 看過，下一次間隔再拉長。`consolidate` 會另外列出決策房裡互相衝突的抽屜，也會寫一份當日摘要放進 `daily_summaries`。這和「寫入當下就自動蓋上已被取代」是兩條路。有沒有一個給人逐張裁決衝突的佇列，原始碼裡沒有這樣的畫面，尚未確認。

### 接上 agent 的門

Python SDK 是主入口，預設宮殿目錄是 `~/.mempalace`，抽屜放在其中的 Chroma collection。MCP 原始碼露出的工具包括 `remember`、`recall`、批次記住與召回、`add_fact`、`query_entity`、`forget`、`evolve`。根 README 的工具清單，和 `examples/cursor_mcp` 裡的名稱不完全相同，以 MCP 原始碼為準。REST 用 `mempalace serve`，可加 API key，預設埠 `8765`。repo 裡也有 OpenAI 與 LangChain 的 adapter 檔，本次沒有跑過。

CLI 的 `remember`、`recall`、`evolve` 沒有 `--wing`。不指定時翼是 `global`。只有 `serve` 能指定翼。README 寫正式使用時一座翼只放一個專案，避免落進預設的 `global`。

## 主打賣點

- 它想被記住的是位子和整理。記憶有翼、有房間、有抽屜。用過的留下，久沒人看的淡掉或被清掉，被別的專案反覆用到的經驗會改成大家都能召回的程序記憶。
- 資料留在本機一個目錄。Chroma 放抽屜文字，SQLite 放關係。MCP、REST、CLI、Python 是同一座宮殿的不同門。
- 向量搜尋、三元組、MCP，是把現成能力裝進這組位子。值得搬進工作空間的是「放在哪一間房」和「閉館時誰把紙搬走」。
- 路線圖要把留下的記憶編成 wiki 頁，模型裡已有 `WikiPage` 和 `Source`。檔案樹裡沒有產生 wiki 的程式。那是計畫。PyPI 徽章指向 `mempalace-evolve`，2026-10-10 查套件頁是 404。文件裡的安裝方式是從 repo 做可編輯安裝。

## 使用情境

### 同一個專案，下一輪還找得到決定

- 適合誰：用 Cursor 或 Claude Code，希望下一輪還記得架構決定的人。
- 在什麼情況使用：一座翼對一個專案，決定放進 `decisions`，設定放進 `config`，下一輪用 `recall` 或 `context_for` 取回。
- 帶來的價值：筆記有房間和來源。換題目時換翼，不會和別的專案抽屜混在同一層。

### 一輪對話結束，有人把重點歸檔

- 適合誰：希望對話收尾時自動留下決定和錯誤的人。
- 在什麼情況使用：掛上 Claude Code 的 Stop hook，或自己把逐字稿交給 `digest` 再 `evolve`。
- 帶來的價值：關鍵字挑出的句子進對應房間，整理時合併重複、清掉太薄的。人之後用 `review` 看到期的那一疊。

### 錯誤經驗從這一翼走到走廊

- 適合誰：同時做幾個專案、希望踩過的錯別的翼也看得到的人。
- 在什麼情況使用：錯誤放進 `errors` 或 `error_patterns`，或等一則記憶被別的翼召回累計三次後升成程序記憶。
- 帶來的價值：召回時除了自己這座翼，還會看到共用經驗。這次沒有實測升格是否如計數所寫。

## 我們可以學什麼

- 值得借鑑的 product idea：記憶是有地址的抽屜。翼是一座樓層的鎖，房間是類別，抽屜是一則帶來源的紙。進化是閉館後的班：合併、淡出、蓋章、把反覆被借走的經驗搬到走廊。
- 值得借鑑的 interaction / workflow：放，是走進房間把紙放進抽屜。找，是從這座翼的房間抽出相關的紙，再看走廊上的共用經驗。被拿過的紙會更新「最後被看」，所以常被用的留在手邊。新決定若蓋過舊的，舊紙留在原抽屜並蓋章，排序往後。間隔複習是工位上到期要再看一次的一小疊卡片，人看過才排下一次。
- 在 2D workspace 裡會變成什麼：一張俯視樓層，pixel 辦公室或平面地圖都可以。你站的這一翼是這一層，別的專案在別層。房間標著決策、架構、設定、錯誤、一般。抽屜是桌上或櫃裡的紙，角上寫來源和新鮮度。開始工作時，身份銘牌和這一翼最重要的十幾張紙先攤在中央桌。問一個問題時，職員從這一層的房間取紙，也到走廊看共用經驗板。這一輪攤開的工作記憶只留在當班的桌上。閉館時有人把重複的紙訂在一起，很久沒人碰的決策套上「可能過時」，被別層借走累計三次的筆記釘到走廊。壓縮是舊紙進檔案箱、桌上只留短摘要。人看得到：哪張紙在哪一間房、哪張被蓋章、哪張搬去了走廊。
- 在 3D workspace 裡會變成什麼：可走進的辦公室，如同 [Agent Office](https://github.com/AgentSystemLabs/agent-office)。你走進這一翼，看見員工在命名的房間裡做事。記住一件事，是某個員工拿著紙走進決策室，放進抽屜。召回是有人走到那間房，抽出資料夾，走回自己的工位接著做。共用經驗在翼與翼之間的走廊，別的專案的人讀得到，不必進入你的房間。閉館時你看見職員在房間之間走動：合併重複的紙，把淡掉的放進檔案間，把被多座翼用過的教訓從私人抽屜搬到走廊，把到期要複習的卡片放在椅子上。已被取代的決定還在原抽屜，上面有章。關係三元組是櫃檯的帳冊，職員用它決定還要多拿隔壁抽屜的哪一張紙。人注意的是誰在哪一間房間收發記憶。
- 需要重新設計的地方：現在的軌跡是 API 和 CLI，辦公室要自己呈現「人在哪一間房」。SDK 召回和四層記憶棧是兩條路，在接上之前，起床時攤開的十五張紙，和 `recall` 拿回來的紙，要分成兩次能看見的動作。CLI 多數指令落在 `global` 翼，樓層上要一直標出你在哪一翼。蓋章用的是相似度，人要走過去看，也能把章撕掉。`evolve` 只數出可壓縮的數量，壓縮和複習是另外的班。SDK 把圖譜寫在宮殿目錄裡的 `knowledge_graph.sqlite3`，部分整理卻用套件旁邊的預設資料庫，兩本帳會不會分開，尚未實測。wiki 頁和靜態網站還在路線圖。REST 的 CLI 預設綁 `0.0.0.0`，安全文件寫 localhost，兩者尚未對齊。

## 初步看法

- 最有價值的部分：翼、房間、抽屜這組地址，加上閉館整理時紙會合併、淡出，或搬到共用走廊。人可以在樓層上看見記憶被放在哪、被誰拿走。
- 最大限制或疑問：它是函式庫，沒有空間畫面。兩條召回路、兩種圖譜路徑、CLI 預設 `global` 翼，以及「已被取代」只靠相似度，都要實測才知道實際會放錯哪一間房。
- 是否值得進一步研究或親自體驗：值得，尤其是放、找、閉館整理這三個動作在 2D 樓層和可走進的辦公室裡怎麼被看見。Status 維持 `untried`。

## 產品介紹

這是一份教學 repo：教你用 [PocketFlow](https://github.com/The-Pocket/PocketFlow) 這個約一百行的 LLM 框架，做一條「把程式庫編成新手教學」的流程。這個 Cell 的來源是這份教學，框架本身是另一個 repo。作者在 README 把讀者放在「剛打開別人的程式、不知道從哪讀」的人。你給一個公開 GitHub 網址，或本機目錄，它依序抓檔、命名少數核心概念、寫出概念怎麼相連、排好章節、逐章寫完，再存成一份 Markdown 教學。

README 說它從程式碼做出 knowledge base。實際寫出來的是一個目錄：`index.md` 加上一章一個檔。它沒有查詢介面，也沒有跑完之後還能繼續問的記憶庫。repo 裡的 `docs/` 是已經生成、並放到 GitHub Pages 的範例教學。本次只讀 `main`（`05b24cbbb0`，2026-05-31）的 README、LICENSE、`docs/design.md`、流程原始碼與一個範例教學，沒有安裝、沒有跑過。

## 主要 Features

### 一張共用桌子上的流程

設計文件把整件事寫成固定順序，不是一組會互相派工的角色。`main.py` 先填一份 `shared` 字典：來源、專案名、GitHub token、輸出目錄、要收／要排除的檔、單檔大小、語言、要不要快取、概念上限。六個節點依序跑：`FetchRepo`、`IdentifyAbstractions`、`AnalyzeRelationships`、`OrderChapters`、`WriteChapters`、`CombineTutorial`。每一步從這份字典讀，做完再寫回去。字典裡接著出現的是：檔案清單、概念、關係、章節順序、各章正文、最後輸出路徑。步驟之間的交接就是這份字典。

### 概念卡指回檔案編號

`FetchRepo` 把篩過的檔收成 `(路徑, 內容)` 清單，順序就是編號。公開 HTTPS 網址走 GitHub API，可帶上 URL 裡的分支、commit 或子目錄；沒給 token 會警告可能碰到 rate limit，碰到 rate limit 會等到重置再抓。程式註解寫私人 repo 需要 token。`git@` 或 `.git` 結尾則 clone 到暫存目錄再讀檔。本機目錄直接讀行程看得到的檔。

`IdentifyAbstractions` 把這批檔的內容一次放進同一個提示，請模型列出大約 5 個到上限（預設 10）的核心概念。每張卡有名字、約一百字的新手說明，以及相關檔案的編號。程式檢查 YAML 形狀，以及編號有沒有超出檔案清單。之後的步驟用編號把檔案拿回來，而不是再掃整棵樹。預設會收常見原始碼、Markdown、YAML、Dockerfile，並排除測試、`docs`、範例、`node_modules` 等。單檔預設上限約 100KB。第一關仍是整包塞進一個提示；檔案篩選是這包會不會太大的主要閘門。大 repo 實際會不會失敗，尚未實測。

### 關係、順序，然後一章一章寫

`AnalyzeRelationships` 產出專案摘要，以及概念之間的短關係：起點編號、終點編號、幾個字的標籤（例如呼叫或傳參數）。提示要求每個概念至少出現在一條關係裡。檢查程式只驗證欄位和編號範圍，沒有檢查是不是每個概念都有連到。`OrderChapters` 請模型依「先講基礎、再講細節」排序，並檢查結果是不是每個概念剛好出現一次。

`WriteChapters` 是 `BatchNode`。每一章只附上該概念點到的檔案、整份章節目錄、上一章與下一章的連結資訊，以及這一輪已經寫完的前文章全文（程式把全文接在一起；設計文件寫的是 summary）。寫完先留在這個節點上，給下一章當上下文，全部寫完才放進 `shared["chapters"]`。章與章的交接是「已經寫好的稿」，不是另一個角色來對話。四個會呼叫模型的節點建立時設了 `max_retries=5`、`wait=20`。YAML 解析失敗或編號不合法會丟出錯誤，讓該節點重試；重試那一次不走快取。正文對不對，沒有再檢查，只在缺標題時補上章名。

### 裝訂成可讀的教學

`CombineTutorial` 在輸出目錄下用專案名開一個資料夾，寫入 `index.md`：摘要、一張 Mermaid `flowchart`（節點是概念名，邊是關係標籤，標籤超過 30 字會截斷）、章節連結、來源 repo。各章是 `01_...md` 這種檔。`--language` 不是英文時，名字、說明、摘要、關係標籤和章節正文會要求用該語言；頁尾的 “Generated by …” 仍是英文。`docs/` 裡已附多份生成結果（含一份講 PocketFlow 框架本身的教學），GitHub Pages 放在 `https://the-pocket.github.io/PocketFlow-Tutorial-Codebase-Knowledge/`。

模型預設走 Gemini：有 `GEMINI_PROJECT_ID` 或 `GEMINI_API_KEY` 就用 Gemini，程式預設模型字串是 `gemini-2.5-pro-exp-03-25`（可用 `GEMINI_MODEL` 改）。否則用 `LLM_PROVIDER`，再讀 `<PROVIDER>_MODEL`、`<PROVIDER>_BASE_URL`、`<PROVIDER>_API_KEY`，打 OpenAI 相容的 `/v1/chat/completions`。README 舉的變數名是 `XAI_URL`，程式讀的是 `XAI_BASE_URL`。`.env.sample` 有 OpenRouter 的 key 和 model，沒有 base URL。照 README 的變數名能不能跑起來，尚未確認。回應可快取在工作目錄的 `llm_cache.json`（整段提示當 key）。同一次呼叫也會寫進 `logs/llm_calls_日期.log`，內容包含送出的提示，因此原始碼會進 log。

Docker 映像是 `python:3.10-slim`，裝 git，進入點是 `python main.py`。README 要你把 API key 放進環境變數，把要分析的目錄和輸出目錄掛進去。這是把這支程式裝進容器，不是給代理一張權限表。

## 主打賣點

- 它要人記住的是這條編譯方式：程式庫先變成少量概念卡，卡片用檔案編號指回來源，再排成有順序的教學。後一章只看自己的檔，加上前面已經寫好的章。
- 流程寫在 PocketFlow 的 Node／Flow 上。PocketFlow 是這份教學使用的框架；框架 repo 是另一個產品。
- 成品是給人讀的 Markdown 教學。它沒有做完之後的問答，也沒有向量索引。Mermaid 是小冊首頁裡的一張圖。
- README 另說這份教學本身是人寫 `docs/design.md`、再由程式代理寫 `flow.py`。那是作者描述的開發方式。生成教學的執行期仍是上面那條一次跑完的流程。

## 使用情境

### 接手一個公開 repo，先有一份閱讀順序

- 適合誰：要讀別人專案、又不想從第一個檔案硬翻的人。
- 在什麼情況使用：有公開 GitHub 網址，願意花一次模型呼叫，換一份依概念分章的教學。
- 帶來的價值：先看到少數概念、它們怎麼相連、建議先讀哪一章，每章只圍繞相關檔案。

### 本機目錄，順便指定語言和要看的檔

- 適合誰：程式在本機、或不想把測試和文件夾進分析的人。
- 在什麼情況使用：`--dir` 指到目錄，用 include／exclude 和檔案大小收窄範圍，`--language` 指定教學語言。
- 帶來的價值：進模型的範圍是人先圈好的；私人 repo 則改走 token 或 SSH clone。權限邊界就是這些開關，沒有再細的代理權限。

### 學「共用狀態的固定流程」長什麼樣

- 適合誰：要看 PocketFlow 怎麼把一個具體工作拆成節點的人。
- 在什麼情況使用：讀 `docs/design.md` 的 shared 結構和六個節點，對照 `flow.py`、`nodes.py`。
- 帶來的價值：看得到任務資料放在哪、上下文怎麼交到下一棒、檢查失敗時是重試同一棒。這和「一組一直在線的員工」是不同的編排。

## 我們可以學什麼

- 值得借鑑的 product idea：程式庫要變成下一個人（或下一個代理）能用的知識時，先留下一小疊概念卡。每張卡有名字、給新手的說明，以及檔案編號。接著是概念之間的短關係、一份教學順序，最後才是章節。後一章的上下文是自己的檔，加上這一輪已經寫好的前文章全文。
- 值得借鑑的 interaction / workflow：人在收件時決定來源、檔案範圍、大小、概念上限、語言、快取。六個位子接著依序做：收檔、命名概念、寫關係、排章節、寫章、裝訂。格式或編號不對，四個模型步驟會在原位重試（最多 5 次，間隔 20 秒）。人等整本出現在輸出目錄再讀。流程裡沒有中途把某一章送回給人改的關卡。
- 在 2D workspace 裡會變成什麼：一張俯視樓層，只服務這一趟「把程式庫編成教學」。收件桌貼著過濾卡片（哪些檔進來、語言、概念上限）。檔案櫃的資料夾按抓取順序編號。概念桌的卡片寫名字和檔案編號，不把整份程式貼上牆。關係是概念之間的短箭頭，畫完抄進小冊首頁；樓層仍是這些工位。寫章的一排桌子標著第幾章；寫完的頁放在桌邊，下一桌讀的是全文。裝訂桌把首頁和各章放進出貨抽屜。人站在收件桌，做完再到出貨抽屜拿小冊。
- 在 3D workspace 裡會變成什麼：可走進的辦公室，如同 [Agent Office](https://github.com/AgentSystemLabs/agent-office)。你進來看誰在場：委託人在前門，手上是 repo 網址或本機資料夾；檔案員在櫃子前；概念、關係、排序各坐一張桌子；寫章的人坐在某一章的位子，桌上有前幾章的稿。你走過去就知道現在做到哪一站、第幾章，以及小冊有沒有放到審閱桌。關係箭頭留在紙上。重點是看見誰在哪裡做事。
- 需要重新設計的地方：這些位子是同一次執行的步驟，跑完就散，不是長期坐班的員工。第一個模型步驟仍把篩過的檔一次送進同一個提示。關係是否涵蓋每個概念，提示有要求，程式沒有檢查。前面概念抓錯，後面章節會整章跟著走，因為沒有人中途改稿。權限就是 token、檔案篩選，以及 Docker 掛載的目錄。log 會记下含原始碼的提示。`code2tutorial.com` 在 2026-10-10 回 404，不要把它畫成已經開著的服務台。

## 初步看法

- 最有價值的部分：用檔案編號把「整包程式」收成概念卡，再讓每一章只帶相關檔和前面的稿。這是工作空間裡「知識怎麼交到下一張桌子」的具體做法。
- 最大限制或疑問：一次跑完、沒有問答、也沒有人審章節。教學品質、大 repo 的第一個提示、以及 README 與程式的模型變數名是否一致，都還沒跑過。線上服務目前打不開。
- 是否值得進一步研究或親自體驗：值得，尤其是概念卡、章節交接、以及人只在收件和收成品時出現，放進 2D 樓層和 3D 辦公室後怎麼被看見。Status 維持 `untried`。

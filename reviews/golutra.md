## 產品介紹

Golutra（官方多半寫成 golutra）是一套本機桌面工作空間。它把你已經裝好的
程式工具收成同一個聊天室：打開一個資料夾當工作區，把 Gemini CLI、Codex、
Claude Code、OpenCode、Qwen Code 或自訂命令邀請成成員，再在頻道裡 @ 他們。
一句話會寫進那位成員背後的終端機；終端機的輸出再收回來變成聊天訊息。點頭像
可以打開真正的終端視窗，看它在做什麼，或直接打字進去。

畫面是 Vue 3，本機殼是 Rust／Tauri，安裝包涵蓋 Windows、macOS、Linux。
主要用法是開這個桌面程式，它是工作空間，不是給別的程式呼叫的函式庫。另外
有一支 `golutra` 命令，透過本機 socket 對已經開著的程式送指令。尚未安裝或
執行。下面關於程式怎麼運作的描述，來自預設分支 `master` 的提交
`8b68a141`（2026-05-12），是讀程式，不是實測。

## 主要 Features

### 聊天室裡的 CLI 成員

工作區就是你選的資料夾。成員分成主人、管理員、助手、一般成員；會開終端的
是助手。內建可選 Gemini CLI（`gemini`）、Codex（`codex`）、Claude Code
（`claude`）、OpenCode（`opencode`）、Qwen Code（`qwen`），以及系統
shell。也可以填一條自訂命令。邀請畫面裡，自訂項的類型被標成 shell，命令
字串仍會送出；最後實際啟動哪一個程式，尚未確認。

一次邀請可以開多個分身。這個畫面把數量卡在 1 到 20。官方介紹寫成不限數量，
和這份程式看到的上限不一致，別的入口能不能超過，尚未確認。

頻道裡的訊息只派給被 @ 的人，或 @ 全體。私訊派給對話裡的另一個人。每位成員
有自己的終端佇列：同一條終端一次送一則，這輪畫面穩定後才送下一則，中間可以
把同情境的句子接在一起；不同成員可以同時跑。成員若是勿擾，這則派送會被略過。

### 終端當員工，聊天當對講機

後端用 PTY 啟動你本機的 CLI，工作目錄是這個工作區。就緒之後會再送一段開場，
告訴它自己的名字，以及它正在跟團隊一起解決問題。Codex 會把 session id 存起來，
下次用 `resume` 接回；這次讀到的其他內建 CLI 沒有同樣的恢復模板。人在聊天室
看到的是頭像、連線狀態與訊息；想看原始過程就打開終端視窗。

### 權限：跳過詢問，以及一顆沙盒勾選

邀請助手時，「無限制模式」預設打開。程式會在預設命令後面加上該 CLI 自己的
跳過確認旗標：Claude Code 是 `--dangerously-skip-permissions`，Codex 是
`--dangerously-bypass-approvals-and-sandbox`，Gemini 與 Qwen 是 `--yolo`。
OpenCode 與 shell 沒有對應旗標。這些行程用的是你登入帳號的權限。

旁邊有「沙盒環境」勾選。建立終端的註解寫明，這組邀請資料（含沙盒）用來做
編排記錄；PTY 啟動路徑沒有另外開一個隔離環境。勾選之後會不會真的隔離，
尚未確認。

### 路線圖、技能資料夾、對外叫它的入口

路線圖是工作區裡的一段目標，加上完成、進行中、待辦的任務清單，存在專案資料
裡。這份程式沒有把清單自動派給成員。人要改任務、改順序、標優先，都在這個
彈窗裡完成。

技能是工作區 `.golutra/skills` 裡的連結，可以從本機技能庫掛進這個工作區。
技能商店與外掛市集的畫面都在，清單資料這次是空的佔位，註解寫著還沒接上來源。

官方介紹說可以呼叫 EverOS 當長期記憶，並用另一個專案 golutra-mcp 走 MCP。
那兩個不在這個 repository 裡，有沒有已經接進這次讀到的主流程，尚未確認。
`golutra` 命令可以對開著的桌面程式送一句聊天指令，再等待結果。這是外面的
工具叫進這個指揮室的入口。

## 主打賣點

- **留著原本的 CLI，換成一個指揮室。** 專案資料夾不用搬走，指令也不用重學。
  平行的單位是成員：每個人一條終端、一條佇列，人用 @ 決定這句話給誰。
- **人和過程留在同一個房間。** 聊天是派工與回報，頭像上的狀態是誰在忙，
  點進去才是原始終端。開場白把「你叫這個名字、你在這個團隊」寫進 CLI，
  身份交接發生在終端輸入，而不是另一套共用記憶。
- **和 Maestro 放在同一層看。** 兩邊都是桌面殼，底下仍是 Claude Code、Codex、
  OpenCode 這類本機 CLI。Maestro 把工作收成可重複的清單與 git worktree。
  Golutra 把工作收成頻道、成員與終端佇列，人站在聊天室裡點名。
- **介紹頁比這份程式走得更前面。** 官方還寫了工作流模板一鍵匯入匯出、頂層
  CEO Agent、最長一個月無人值守，以及 OpenClaw 圖示。這次讀到的內建成員
  型別沒有獨立的 openclaw，也沒有工作流執行器。那些是介紹與後續方向，
  尚未確認。

## 使用情境

### 同一個資料夾裡同時叫幾位熟悉的 CLI

- 適合誰：已經在用 Codex、Claude Code 或 OpenCode，想少切幾個終端視窗的人。
- 在什麼情況使用：打開專案資料夾，邀請兩三位助手，在預設頻道 @ 指定的人，
  或開私訊只跟一位說話。
- 帶來的價值：每個人有自己的終端與佇列，回報回到同一間聊天室，人不必在多個
  視窗之間複製上下文。

### 派工之後走到某張桌子後面看

- 適合誰：要確認 CLI 有沒有真的收到字、卡在詢問，或自己想插一句的人。
- 在什麼情況使用：點成員頭像打開終端視窗，看連線狀態從連接中到工作中，
  必要時直接打進那條 PTY。
- 帶來的價值：聊天訊息和原始終端是同一位員工的兩面，介入不用離開這個工作區。

### 讓外面的指令對已經開好的團隊說一句話

- 適合誰：想用本機命令或之後的 MCP 入口，把一句話送進正在跑的 Golutra。
- 在什麼情況使用：桌面程式開著，用 `golutra send` 指定工作區、發送者與
  對話，再 `golutra wait` 等結果。
- 帶來的價值：指揮室可以留在桌面，外部工具只負責把一句話送進去。這條路徑
  尚未實測。

## 我們可以學什麼

- 值得借鑑的 product idea：把「一位 CLI」畫成聊天室裡的一位成員。分身、
  勿擾、私訊與 @ 全體，都是人已經懂的編排語言。平行發生在不同成員之間，
  同一條終端保持一次一件事。
- 值得借鑑的 interaction / workflow：派工走聊天，驗收看終端。狀態燈
  （連接中、已連接、工作中、離線，以及成員的勿擾）讓人知道該不該再丟下一句。
  開場白把名字與團隊角色寫進 CLI，是很輕的 handoff。Codex 的 session 恢復
  則把「這位員工昨天坐在哪」留了下來。
- 在 2D workspace 裡會變成什麼：一層俯視的樓層。每位 CLI 成員是一張工位，
  桌上有連線燈。頻道是這層的公告牆，@ 某人就是把紙條送到那張桌子；私訊是
  走到桌邊說話。同一張桌子一次只處理一張紙條，不同桌子可以同時亮著。路線圖
  白板掛在牆上，人可以改目標和待辦。點工位會掀開那台終端。無限制模式是桌上
  的牌子，表示啟動時跳過 CLI 的詢問。
- 在 3D workspace 裡會變成什麼：一間走得進去的辦公室。Gemini、Codex、
  Claude Code 各坐一張桌子，同一種 CLI 的分身是相鄰的幾張桌子。誰在打字、
  誰關著門勿擾，走過去就看得到。人可以站到某位員工背後看螢幕，或在鍵盤上
  插一句。頻道是中間的討論區，被點名的人起身回應。路線圖是牆上的白板，人
  站在前面改任務。重點是誰在場、誰在忙、訊息送到哪一張桌子。
- 不值得照搬或需要重新設計的地方：無限制模式預設打開，等於預設拿掉 CLI
  的許可詢問。沙盒若只寫在邀請記錄裡，不能當成隔離。聊天室的樣子容易讓人
  以為已經有共同記憶和自動分工；這份程式的分工仍主要靠人點名，路線圖也不會
  自己派人。技能商店與外掛市集有畫面、清單仍是空的。介紹頁上的 CEO、長期
  無人值守與工作流模板，還不能當成這間辦公室已經有的規則。

## 初步看法

- 最有價值的部分：成員、@、終端佇列與可打開的 PTY，把多個本機 CLI 收成
  看得到人的指揮室。這比再包一層聊天視窗更接近「誰在哪裡做事」。
- 最大限制或疑問：權限預設偏向跳過詢問；沙盒勾選有沒有隔離，尚未確認。
  路線圖、技能商店、工作流模板與 OpenClaw 成員，介紹和程式對不上的地方
  都還沒跑過。授權檔是 Business Source License 1.1（Change Date
  2030-02-25，之後為 GPL-2.0-or-later，額外使用授權寫 None）。README 另寫
  可以拿它當工具做商業軟體，使用者產出歸使用者。兩份文字怎麼一起讀，尚未確認。
- 是否值得進一步研究或親自體驗：值得看桌面裡 @ 與終端是否同一位員工，以及
  多成員同時跑時人能不能跟上。這次沒有執行。

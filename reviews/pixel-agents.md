## 產品介紹

Pixel Agents 是一間俯視的像素辦公室。正在跑的 AI coding agent 會變成樓層上的小人：走到自己的椅子、坐下、依手上的工具打字或閱讀，卡住時頭上冒泡泡。像素畫就是工作場所本身。你在這層樓上看誰在場、誰在做事、誰在等你。

它有兩種進入方式，共用同一套樓層。VS Code 擴充功能把辦公室畫在終端機旁邊的面板，按一下可以從這裡啟動 Claude Code。獨立程式在專案目錄執行後，用瀏覽器開同一間辦公室，適合 tmux、遠端、或不在 VS Code 裡工作的人。文件與程式碼目前只接上 Claude Code；Codex、Gemini、Cursor 等寫在路線圖上，尚未確認已可用。回覆和批准仍在那個 agent 的終端機裡完成。點小人，是把對應終端叫到前面。

## 主要 Features

### 一個 agent 一個角色

每個被追蹤的 Claude Code 工作階段都有自己的小人、座位和顏色。從辦公室啟動的，以及外面已經在跑、後來被收進來的，都佔一個位子。沒有終端可聚焦的 headless 工作階段，可以選擇畫成半透明的 Ghost。我們尚未跑過，Ghost 的預設是關閉。

### 動作跟真實工具走

預設用 Claude Code 的 hook 推送狀態；沒有 hook 時，改掃工作階段紀錄來推論。正在做事的小人坐在桌前。讀檔、搜尋用閱讀動畫，寫檔、改檔、跑指令用打字動畫。頭上有一行活動說明，以及該工作階段的 context 用量條。做完一輪會離開座位閒逛。等人回覆或等人批准時，留在座位上。

### 泡泡把「沒在做事」分成三種

做完一輪是會自己淡掉的勾。等人輸入會停著，並標出正在等你。等人批准工具是另一種停住的泡泡，而且可以發生在回合中間。可選音效在回合結束或請求權限時提醒。點角色會聚焦那個終端；座位可以改，選中小人再點空椅即可。

### 臨時幫手與隊友佔不同的空間

沒有名字的 sub-agent 不佔椅子，站在叫出它的那個人旁邊，事情做完就消失。有名字的 teammate 是團隊成員，坐在離 Lead 最近的空位，頭上有角色標籤。臨時工作和正式成員，用「有沒有自己的座位」分開。

### 樓層可以編，Area 對應資料夾

內建編輯器能畫地板、牆、地毯和家具，格子可以加大，版面能匯出，也能載入外部的角色和家具包。Area 是命名區域：把 workspace 資料夾對應上去之後，從那個資料夾來的 agent 會優先坐進那一區。寵物會自己走，文件把它定義成不屬於任何 agent 的裝飾。

### 兩個表面看同一層樓

VS Code 和獨立伺服器可以同時開。Hook 事件會送到每一個正在跑的伺服器，兩邊各自保留 agent、座位和設定，共用的是辦公室版面。獨立模式預設只綁本機。瀏覽器網址裡的 token 才能同意安裝 hook；沒有 token 的人可以看辦公室，不能改那份設定。

## 主打賣點

- 它最想被記住的是：同時看很多 agent，可以像在看一間小辦公室，而不是在分頁之間做行政。官方把方向寫成「玩一款遊戲，同時把產品做出來」。
- 已經做出來的差異，是用平面樓層編碼狀態：座位、閒逛、泡泡、Area、子任務與隊友。這是工作場所，ADE 側欄另計。
- 編排仍停在下一階段。額度顯示、會改變工作的家具、一個專案一間存檔、拖選組隊、把工作交給別人、指著看板讓他們自己領任務，都還在願景裡。現在的工作本體仍是 Claude Code 終端。
- 和已收錄的 Agent Office 放在一起看：那邊是可走進去的 3D 辦公室，終端在桌上的筆電。Pixel Agents 是俯視樓層，人留在畫面外，掃一眼就看到誰在打字、誰在等。

## 使用情境

### 一個人同時看很多 Claude Code

- 適合誰：同時開好幾個 Claude Code 工作階段的開發者。
- 在什麼情況使用：想知道誰在改檔、誰在等批准、誰已經做完。
- 帶來的價值：樓層上的姿勢和泡泡就是狀態，不必逐個終端翻。

### 在 VS Code 裡邊寫邊看辦公室

- 適合誰：主要在 VS Code 裡用 Claude Code 的人。
- 在什麼情況使用：終端在跑，旁邊的面板即時反映工具動作。
- 帶來的價值：點卡住的小人就回到那個終端，批准和回覆留在原本的地方。

### 用瀏覽器看同一層樓

- 適合誰：用 tmux、遠端機器，或想脫離 VS Code 看狀態的人。
- 在什麼情況使用：在專案目錄啟動獨立程式，讓已經在跑的 Claude 工作階段出現在辦公室。
- 帶來的價值：編輯器可以換，座位和泡泡的語言可以留著。多人一起操作、以及手機是否順手，尚未確認。

## 我們可以學什麼

- 值得借鑑的 product idea：像素樓層可以是工作空間本體。一個 agent 一個角色，一張椅子一個座位，一個資料夾一塊 Area。狀態從工具事件來。
- 值得借鑑的 interaction：三種「沒在做事」要分得開。做完的人可以離開座位；等人說話的人坐著；等人批准的人坐著，而且訊號不自己消失。沒有名字的幫手不佔椅子，有名字的隊友才入座，並且坐在 Lead 附近。點人是去終端，地板上不必再做一套聊天。
- 在 2D workspace 裡會變成什麼：它已經是這種平面樓層。俯視要繼續看得到的是誰坐在哪一區、頭上的活動字、context 條、停住的權限泡泡，以及做完之後在走的人。樓層編輯器要服務「這區是哪個資料夾」。寵物、地毯和色調可以留，它們不該蓋過座位規則。
- 在 3D workspace 裡會變成什麼：同一套在場語言走進去看。做事的人坐在桌前打字或看螢幕；做完的人離開桌子在辦公室裡走；卡住的人留在位子上，權限請求和等人回覆用兩種不同的訊號。Sub-agent 站在帶他的那個人旁邊，不佔正式桌子；有名字的隊友圍在 Lead 附近。Area 變成可走進去的區域，仍然對應資料夾或 repo。點人仍然打開那張桌上的終端。走進去時值得留下的是誰在場、卡在哪張桌子、臨時幫手沒有自己的位子。平面樓層仍然要顯示同一件事的俯視版：座位、區域、泡泡、活動字，讓人不用走過去也能掃完整層。
- 需要重新設計的地方：拖選組隊、交接、看板領任務還不能當成現成能力。只換外觀、不改變工作的家具，不要算成編排功能。Hook 會寫入使用者的 Claude 設定，獨立模式的網址 token 能同意安裝，這要當權限邊界看。多工具辦公室尚未確認。

## 初步看法

- 最有價值的部分：它讓像素樓層承載 agent 狀態。子任務、隊友、資料夾區域已經有空間語法。
- 最大限制或疑問：介入和真正的工作都還在終端。官方自己把交辦、組隊、看板放在下一階段。我們沒有跑過，動畫是否跟工具對得上，尚未確認。
- 是否值得進一步研究或親自體驗：值得。它是目前目錄裡直接把平面像素樓層當工作場所的產品，和 Agent Office 那種可走入的 3D 辦公室回答的是同一件事的兩種空間密度。
